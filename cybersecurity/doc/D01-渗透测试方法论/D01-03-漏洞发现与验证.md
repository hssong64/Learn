# D01-03 · 漏洞发现与验证

## 学习目标

- 会组合扫描器 + 手工方法
- 掌握验证与去误报
- 建立优先级排序能力

## 一、发现手段

| 手段 | 擅长 | 短板 |
|------|------|------|
| 漏洞扫描器 | 已知 CVE、配置、常见洞 | 逻辑/越权弱、误报 |
| 爬虫 + 被动代理 | 收集请求面 | 需要登录/业务流 |
| 目录/参数 fuzz | 隐藏入口、参数 | 噪音大 |
| 手工测试 | 逻辑、越权、鉴权 | 慢、依赖经验 |
| 代码审计（如有源码） | 深层逻辑 | 需授权与阅读量 |
| 渗透辅助工具 | SQLi/XXE 等专项 | 要理解原理 |

## 二、手工测试优先顺序（Web）

```text
1. 配置与信息泄露
2. 认证与会话
3. 对象级授权（越权/IDOR）
4. 输入类（XSS/SQLi/命令/模板）
5. 文件与解析
6. SSRF/XXE/反序列化
7. 业务逻辑与并发
8. 依赖组件
```

## 三、验证原则

1. **可复现**：步骤完整，别人能重复
2. **最小影响**：不破坏生产、不拖数据
3. **去误报**：扫描器结果必须人工确认
4. **定影响**：结合上下文定级
5. **留证据**：请求/响应/时间戳/测试账号

## 四、去误报清单

| 现象 | 可能误报原因 |
|------|----------------|
| 反射「XSS」 | 被编码/Content-Type 不是 HTML |
| SQL 报错 | 框架统一报错并非注入 |
| 403 就是越权 | 可能只是路由不存在 |
| CVE 命中 | 版本识别错、组件未启用 |
| HTTPS 弱套件 | 内网限制工具 |

## 五、优先级（参考）

| 级别 | 例子 |
|------|------|
| 严重 | RCE、任意文件读写、大面积拖库、认证绕过接管管理员 |
| 高 | 存储型 XSS、SQL 注入、垂直越权、支付逻辑 |
| 中 | 反射型 XSS、CSRF 敏感操作、信息泄露 |
| 低 | 低影响信息泄露、缺安全头 |
| 提示 | 加固建议、最佳实践 |

**业务影响优先于漏洞类型本身。** 反射 XSS 在内网后台可能高危；在宣传页可能低危。

## 六、请求记录模板

```text
标题：
端点：METHOD /path
测试账号：userA / userB
时间：
请求：
响应（关键片段）：
影响：
修复建议：
```

## 七、误报处理流程

1. 复现
2. 换输入/换上下文再试
3. 与开发确认设计
4. 若是防护生效导致，记录「已防护」
5. 无法证明则降级或不报

## 动手练习

1. 用扫描器扫 DVWA，人工确认 5 条并去掉误报
2. 同一漏洞写「给开发」和「给管理层」两个版本描述
3. 建立自己的请求记录模板（Markdown）
