# D01-05 · 渗透报告撰写

## 学习目标

- 会写可交付的渗透测试报告
- 能针对开发、安全、管理层输出不同颗粒度
- 用报告推动修复，而不是交差

## 一、报告结构（推荐）

```text
1. 封面与文档控制（版本、密级、测试时间）
2. 管理层摘要（风险结论、Top 问题、优先级）
3. 测试范围与方法
4. 风险统计（数量、等级分布、对比）
5. 漏洞详情（按优先级）
6. 加固建议总览
7. 附录（工具、请求包、术语、清理记录）
```

## 二、单个漏洞条目模板

```markdown
### [高危] 订单金额可篡改为 0

- 位置：POST /api/pay
- 影响对象：支付模块 / 全量用户
- CVSS/业务定级：高
- 复现步骤：
  1. ...
  2. ...
- 证据：（请求/响应/截图）
- 风险说明：攻击者可 0 元下单，造成直接资金损失
- 修复建议：服务端计价；状态机校验；回调验签
- 复测状态：未修复
```

## 三、三类读者

| 读者 | 要看 | 写法 |
|------|------|------|
| 管理层 | 总体风险、业务影响、投入 | 少术语，多钱/合规/声誉 |
| 开发 | 复现、根因、怎么改 | 精确到接口/代码建议 |
| 安全/运维 | 检测、加固、监控 | 补充规则与日志点 |

## 四、写作规范

1. **标题带危害**，不要只写「发现 XSS」
2. **步骤可复制**，参数写清楚
3. **截图清晰**，关键字段高亮；敏感数据脱敏
4. **影响要业务化**：丢数据/丢钱/合规/用户量
5. **建议要可落地**：参数化、鉴权点、配置项
6. **不夸大不缩小**；误报单独记录不进正式漏洞数

## 五、风险统计表示例

| 等级 | 数量 | 代表问题 |
|------|------|----------|
| 严重 | 1 | 任意文件上传 RCE |
| 高 | 3 | SQL 注入、垂直越权、支付逻辑 |
| 中 | 5 | 反射 XSS、CSRF |
| 低 | 6 | 缺安全头、信息泄露 |
| 提示 | 4 | 加固建议 |

## 六、优先修复建议（给管理层的表述）

1. **立即**：影响资金/认证/代码执行的问题
2. **本迭代**：注入、越权、存储型 XSS
3. **规划内**：安全头、依赖升级、监控告警
4. **持续**：SDL、安全培训、代码审计

## 七、常见报告问题

| 问题 | 改进 |
|------|------|
| 只有截图 | 补文字步骤与请求 |
| 只有漏洞类型 | 补业务影响 |
| 修复建议一句「过滤输入」 | 写清哪里、怎么滤 |
| 等级虚高 | 按上下文与影响 |
| 无复测 | 增加复测章节 |

## 八、交付与沟通

1. 交付前内部 QA（复现一次）
2. 先口头同步高危，再给全文
3. 修复过程答疑（但不替开发写完整补丁，除非合同）
4. 复测报告单独或附录
5. 全文按密级管理

## 动手练习

1. 把前面靶场任意 3 个漏洞写成正式报告条目
2. 用 10 句话写「给 CTO 的管理层摘要」
3. 对比：技术版 vs 管理版同一漏洞的表述差异

## 自测

1. 为什么标题要带危害而不是只带类型？
2. 误报应放在报告的哪里？
3. 复测报告的核心内容？
