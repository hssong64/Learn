# D01-04 · 漏洞利用与后渗透

## 学习目标

- 理解利用阶段的目标与边界
- 知道提权、横移、痕迹清理的基本概念
- 明确「演示影响」与「破坏系统」的差别

> **授权提醒**：后渗透常触碰内网与权限边界，必须书面写入授权范围。

## 一、利用阶段目标

```text
证明漏洞可被利用 → 评估真实影响（权限、数据、范围）→ 为修复提供依据
```

不是：炫技、扩大战果到授权外、破坏业务。

## 二、利用深度分级

| 级别 | 做法 | 适用 |
|------|------|------|
| L0 仅验证 | 回显 PoC | 默认首选 |
| L1 有限利用 | 读测试数据、低权限 shell | 需要评估影响时 |
| L2 控制 | 管理员/主机权限 | 明确授权红队 |
| L3 横移 | 内网其他系统 | 必须单独授权 |

**默认做到能证明风险为止，不为「拿下 root」而滥用。**

## 三、Web 后常见利用链（概念）

```text
Web 注入/上传 → WebShell
  → 服务器低权限用户
    → 提权（sudo/SUID/内核/配置）
      → 凭据（历史、配置、内存、数据库）
        → 内网横移（SMB/SSH/RDP/服务漏洞）
          → 目标资产（域控、数据库、文件）
```

## 四、提权（Linux/Windows 概念）

| 路径 | 线索 |
|------|------|
| 配置 | sudo -l、SUID、可写 cron、PATH |
| 服务 | 错误权限、未引号服务路径 |
| 凭据 | 配置文件、bash_history、明文口令 |
| 组件/内核 | 已知本地提权漏洞 |
| 容器 | 挂载 docker.sock、特权容器 |

## 五、横移与持久化（概念）

- 拿凭据后用合法协议移动（SSH、WinRM、SMB）
- 哈希传递、票据、委派（Windows 域，进阶）
- 持久化：计划任务、启动项、后门——**测试结束必须清理**

## 六、痕迹与清理

| 类型 | 例子 |
|------|------|
| 账号 | 测试账号删除/禁用 |
| 文件 | WebShell、工具、临时文件 |
| 日志 | **不建议乱删**；应记录自己操作便于审计 |
| 配置 | 恢复被改配置 |
| 进程/服务 | 停掉测试用进程 |

最佳实践：**测试前快照/备份，测试后按清单清理并出清理报告。**

## 七、应对运维/应急视角

- 异常账号、异常计划任务
- 出网连接、异常进程
- 文件新增（WebShell）
- 登录异常（时间、来源、行为）

## 八、报告中的利用章节怎么写

1. 利用前提（需要什么漏洞/权限）
2. 步骤（可复现、可授权）
3. 达到的权限与可见数据范围
4. 影响评估
5. 已清理的测试痕迹
6. 修复与检测建议

## 自测

1. 为什么默认不建议直接上「免杀远控」？
2. 测试结束后为什么要交清理清单？
3. 横移为何必须单独授权？
