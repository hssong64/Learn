# D01-01 · 渗透测试标准流程

## 学习目标

- 掌握从接单到结项的完整生命周期
- 理解 PTES / OWASP WSTG / 网络安全法下的交付边界
- 建立「流程纪律」比「单点 payload」更重要的观念

## 一、主流程

```text
1. 前期交互（授权、范围、目标、规则）
2. 信息收集（被动 → 主动）
3. 威胁建模与攻击面分析
4. 漏洞发现（扫描 + 手工）
5. 漏洞验证（最小 PoC）
6. 利用与后渗透（在授权范围内）
7. 报告输出
8. 复测与修复验证
```

## 二、阶段详解

### 1. 前期交互

| 产出 | 内容 |
|------|------|
| 授权书 | 目标、时间、方法、联系人 |
| 范围清单 | 域名/IP/应用/账号 |
| 规则 | 禁止项（DoS、社会工程是否允许） |
| 沟通机制 | 紧急停止、中间同步 |

**没有这一步，后面全部作废。**

### 2. 信息收集

- 被动：搜索引擎、证书透明度、备案、GitHub、历史解析
- 主动：子域、端口、目录、指纹（仅授权范围）
- 产出：资产清单、攻击面图

### 3. 威胁建模

问：最值钱的资产是什么？攻击者最短路径是什么？  
（用户数据、资金、内网、源码、凭据…）

### 4. 漏洞发现

- 自动化：扫描器、爬虫、fuzz
- 手工：越权、逻辑、鉴权、业务
- **不要只信扫描器**

### 5. 验证

- PoC 最小化：证明漏洞存在与影响即可
- 不下载真实敏感数据；测试数据用标记名

### 6. 利用与后渗透（可选，看目标）

- 权限提升、横移、持久化 **仅在明确授权**
- 记录每一步，便于报告与清理

### 7. 报告

- 管理层摘要 + 技术详情 + 修复建议 + 风险评级

### 8. 复测

- 修复后同步骤复现
- 更新报告状态

## 三、不同标准的侧重点

| 标准 | 侧重点 |
|------|--------|
| PTES | 企业渗透全流程 |
| OWASP WSTG | Web 测试清单 |
| OWASP ASVS | 应用安全验收标准（开发向） |
| NIST / 等保 | 合规与体系 |

## 四、时间分配参考（1–2 周 Web 项目）

| 阶段 | 占比 |
|------|------|
| 交互与准备 | 10% |
| 信息收集 | 20% |
| 发现与验证 | 40% |
| 利用（若需要） | 15% |
| 报告与复测 | 15% |

## 五、质量门禁

- [ ] 100% 目标在授权内
- [ ] 每个漏洞有可复现步骤
- [ ] 风险有业务影响描述
- [ ] 修复建议可落地
- [ ] 测试残留已清理（账号、文件、权限）
