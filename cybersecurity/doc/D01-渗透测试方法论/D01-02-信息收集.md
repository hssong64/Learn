# D01-02 · 信息收集

## 学习目标

- 掌握被动/主动信息收集方法
- 能整理可用的资产清单
- 明确信息收集的合法边界

## 一、目标

把「一个域名」扩展成：

```text
子域、IP、端口、服务、技术栈、人员/邮箱、历史数据、攻击面
```

并去重、分级（核心/边缘）、标注是否在授权范围。

## 二、被动收集（不直连目标）

| 类别 | 来源 |
|------|------|
| 备案/主体 | ICP、企业信息 |
| 证书透明度 | crt.sh、各 CT log |
| 搜索引擎 | 子域、目录、错误页、API |
| 历史解析 | SecurityTrails 类历史 |
| 代码托管 | GitHub/GitLab 密钥、配置、内网地址 |
| 社交/招聘 | 技术栈、邮箱格式 |
| 威胁情报 | 历史恶意样本关联（慎用） |

**优点**：隐蔽、合法风险低（仍要遵守站点 ToS 与法律）。

## 三、主动收集（会触达目标）

| 类别 | 内容 |
|------|------|
| DNS | 枚举、AXFR、记录分析 |
| 子域名 | 字典爆破、API、爬虫 |
| 端口 | nmap 慢扫/服务识别 |
| 目录/参数 | 目录爆破、JS 里挖 API |
| 指纹 | CMS、框架、CDN、WAF |
| 爬虫 | 站点结构、表单、隐藏参数 |
| 技术源 | HTTP 头、错误页、favicon hash |

**必须在授权范围与时间窗内；控制速率，避免影响业务。**

## 四、前端同学特别有用的技术源

1. **JS 文件**：API 路径、内网地址、测试密钥、路由
2. **Source Map**：泄露源码
3. **Swagger/OpenAPI**：完整 API 面
4. **webpack chunk 名**：技术栈
5. **前端路由**：隐藏后台入口
6. **注释与调试开关**

```text
拉取所有 JS → 正则挖 URL/密钥/内部域名 → 对照文档找未授权接口
```

## 五、资产整理模板

| 字段 | 示例 |
|------|------|
| 域名/IP | api.example.com / 1.2.3.4 |
| 端口/服务 | 443/HTTPS Nginx |
| 技术栈 | React + Spring |
| 是否核心 | 是 |
| 备注 | 登录口、WAF |

## 六、工具清单（先会思想）

- DNS：`dig`、`nslookup`
- 子域：oneforall、subfinder、各类 API（合规使用）
- 端口：nmap、masscan（注意速率）
- 目录：ffuf、dirsearch、gobuster
- 爬虫：Burp、Katana、自写
- 指纹：Wappalyzer、whatweb

## 七、边界提醒

- 只收集授权范围内资产
- 不要扫 IDC/云段「碰运气」
- 不要下载并公开他人源码/数据
- 速率与时段避开业务高峰（若合同约定）

## 动手练习

1. 对本地靶场做一次完整资产表
2. 从一个前端项目 `dist` 的 JS 里挖出所有 API
3. 写一份「被动收集 1 小时」清单（不打真实未授权目标）

2. JS 源码泄露为什么高价值？
3. 资产表在报告里有什么用？
