# C02-08 · 逻辑漏洞与业务安全

## 学习目标

- 建立业务逻辑测试思维
- 认识支付、并发、流程、验证码等常见逻辑洞
- 知道为什么扫描器扫不出逻辑漏洞

## 一、什么是逻辑漏洞

功能「技术上成功执行」，但**业务规则被绕过或滥用**。

| 特征 | 说明 |
|------|------|
| 无固定 payload | 要理解业务 |
| 扫描器弱 | 缺少业务上下文 |
| 影响大 | 直接钱、库存、数据、资格 |

## 二、常见逻辑漏洞清单

### 1. 支付 / 金额

| 点 | 问题 |
|----|------|
| 前端算价 | 改 JS/包价 |
| 负数/小数 | 金额溢出、0 元购 |
| 优惠券 | 重复使用、并发叠加、越权领 |
| 订单 ID | 可改支付金额、可改支付状态 |
| 回调 | 支付回调不验签、可重放 |

### 2. 流程绕过

```text
正常：下单 → 支付 → 发货 → 收货
绕过：直接调发货接口 / 跳过支付状态机
```

- 步骤可跳
- 状态机不校验前置
- 验证码可爆破或响应里返回

### 3. 越权与平行

- 修改地址看到别人订单
- 手机号改绑无校验
- 企业成员认领他人资源

### 4. 并发与竞态

```text
并发领券 / 并发秒杀扣库存
→ 应用层判断不原子
→ 超卖、重复领、余额翻倍
```

修复：数据库原子操作、分布式锁、幂等键。

### 5. 验证码与频率

- 图形/滑块可打码平台
- 短信轰炸（未限频）
- 邀请码可遍历

### 6. 信息与爬虫

- 接口无鉴权批量拉数据
- 越权导出
- 限流缺失导致拖库式爬取

## 三、测试方法（业务型）

1. **画状态机**：对象有哪些状态、合法迁移
2. **改包三件套**：参数、顺序、并发
3. **双账号**：A 的流程对 B 的对象
4. **极端值**：0、-1、超大、小数、空、数组
5. **重放**：同一回调/短信/支付凭证
6. **时序**：先发货后支付
7. **客户端信任**：删掉 JS 校验再提交

## 四、报告怎么写逻辑洞

```text
标题：订单支付金额可被篡改为 0
步骤：1) 正常下单 2) 拦截支付请求 3) 修改 amount=0 4) 支付成功
影响：可 0 元提货，资金损失
建议：服务端以商品价目表为准计算；回调验签；状态机校验
```

关键是**业务影响**与**可落地修复**，不是 payload 炫技。

## 五、防守视角

- 所有关键计算在服务端
- 状态机 + 权限 + 幂等
- 优惠/库存/资金操作原子化
- 关键操作审计与风控规则
- 压力与并发测试纳入 SDL

## 动手练习

1. 选一个电商 Demo，写 10 条逻辑测试用例
2. 用 Burp 改金额/数量，观察服务端是否以客户端为准
3. 对秒杀场景写「防超卖」方案（数据库/锁/队列）
