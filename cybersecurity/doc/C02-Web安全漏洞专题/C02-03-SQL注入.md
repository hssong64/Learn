# C02-03 · SQL 注入

## 学习目标

- 理解注入本质与参数拼接问题
- 会手工判断、联合查询、布尔/时间盲注（概念+基础）
- 掌握参数化/ORM/最小权限等修复

## 一、原理

查询由**不可信输入拼接**而成，输入改变了 SQL 语法结构。

```sql
-- 代码
"SELECT * FROM users WHERE id = " + uid

-- uid = 1 OR 1=1
SELECT * FROM users WHERE id = 1 OR 1=1
```

**与 XSS 对比**：XSS 注入到 HTML 上下文；SQLi 注入到 SQL 上下文。核心都是「数据 → 代码/命令」。

## 二、注入位置与类型

| 维度 | 类型 |
|------|------|
| 位置 | GET/POST/JSON/Cookie/Header/二次注入 |
| 回显 | 报错型、联合查询、布尔盲注、时间盲注 |
| 数据库 | MySQL、MSSQL、PostgreSQL、SQLite、Oracle 语法有差异 |
| API | REST 参数、GraphQL、存储过程 |

## 三、手工判断（靶场）

1. 加 `'`、`"`、`')` 看报错/行为变化
2. `AND 1=1` / `AND 1=2` 布尔差异
3. `ORDER BY N` 探测列数
4. `UNION SELECT …` 看回显位
5. 盲注用 `SLEEP(5)` / `BENCHMARK`（时间）或真假页面差异（布尔）

```sql
' OR '1'='1
' UNION SELECT null,version(),null--
1' AND IF(1=1,SLEEP(3),0)--
```

> SQLMap 自动化是工具能力，**原理要在手工阶段搞懂**，否则报告写不出、WAF 下不会绕。

## 四、危害

| 危害 | 说明 |
|------|------|
| 读数据 | 用户、订单、密码哈希 |
| 改/删数据 | 完整性破坏 |
| 认证绕过 | `' OR 1=1--` |
| RCE | 结合 `xp_cmdshell`、UDF、`INTO OUTFILE` 等（数据库配置相关） |
| 内网探测 | 结合 SSRF/外带 |

## 五、自动化工具（概念先建）

- **SQLMap**：自动检测与利用，`-u`、`--data`、`--cookie`、`--level`、`--risk`
- 只对授权靶场使用；高 risk/爆破选项容易造成业务影响

## 六、修复（必须背熟）

### 1. 参数化查询 / 预编译（首选）

```python
# 危险
db.execute(f"SELECT * FROM users WHERE name='{name}'")

# 安全
db.execute("SELECT * FROM users WHERE name=%s", (name,))
```

### 2. ORM 安全用法
不要自己拼 `where: string`；用参数绑定 API。

### 3. 最小权限
应用账号禁 `FILE`、`SHUTDOWN` 等；分离读写库。

### 4. 其他
- 白名单排序字段、表名（列名不能参数化时）
- WAF 仅作辅助
- 统一错误页，不回显 SQL
- 二次注入：不要把「已存数据」当可信
