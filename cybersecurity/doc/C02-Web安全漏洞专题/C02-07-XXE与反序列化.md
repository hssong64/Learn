# C02-07 · XXE 与反序列化

## 学习目标

- 理解 XML 外部实体注入
- 理解不安全反序列化如何导致 RCE
- 知道在哪些框架/接口会遇到

## 一、XXE（XML External Entity）

### 原理

应用解析 XML 时允许外部实体，攻击者定义实体指向本地/内网资源。

```xml
<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<user><name>&xxe;</name></user>
```

### 危害

| 用法 | 结果 |
|------|------|
| `file://` | 读本地文件 |
| `http://` | SSRF |
| 参数实体 + 外带 | 带外数据泄露（OOB） |
| 拒绝服务 | 递归实体「亿倍」膨胀 |

### 常见出现点

- SOAP、SVG、Office 文档、SAML、`.docx/.xlsx` 解析
- 接口 `Content-Type: application/xml`
- 网站地图、RSS、老旧 WebService

### 修复

```text
禁用外部实体与 DTD
使用 JSON 等更简单格式（能换则换）
及时更新 XML 解析库
最小权限读文件
```

## 二、不安全反序列化

### 原理

把不可信字节流还原成对象时，触发 `readObject` / `__wakeup` / `__destruct` 等魔法方法，执行危险操作。

```text
攻击者构造恶意序列化数据
  → 应用反序列化
  → 调用链（Gadget Chain）走到 Runtime.exec 等
  → RCE
```

### 常见生态

| 语言/组件 | 关键词 |
|-----------|--------|
| Java | `ObjectInputStream`、fastjson、jackson、log4j 周边 |
| PHP | `unserialize()` + 魔术方法 |
| Python | `pickle`、`yaml.load` |
| .NET | `BinaryFormatter`（危险） |

### 危害

- 远程代码执行
- 拒绝服务
- 绕过认证（会话对象被伪造）
- SSRF、文件写入（视链）

### 修复

1. 不要反序列化不可信数据
2. 使用安全格式（JSON）+ 严格 schema
3. 白名单允许的类（Java JEP 290 等）
4. 升级框架，关注安全公告
5. `yaml.safe_load`，禁用 `pickle` 网络传输

## 三、与其他漏洞的组合

| 组合 | 效果 |
|------|------|
| XXE + SSRF | 打内网/云元数据 |
| 反序列化 + 会话 | 伪造登录态 |
| 文件上传 + 解析 | 上马执行 |
| 注入 + 文件写 | 落地持久化 |

## 四、检测与测试思路

- 看 Content-Type 是否接受 XML
- 发送含 DOCTYPE 的探针看报错/延迟
- 看接口是否接受序列化字段（`rO0AB` Java 头等）
- 关注依赖组件漏洞通告
