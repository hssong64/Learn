# C02-05 · 身份认证与会话安全

## 学习目标

- 掌握认证/会话/授权漏洞的常见形态
- 理解 JWT、OAuth 的风险点
- 会检查越权（水平/垂直/IDOR）

## 一、认证漏洞

| 问题 | 表现 | 修复 |
|------|------|------|
| 弱口令 | admin/123456 | 强度策略、泄露口令检测 |
| 无锁定 | 可无限爆破 | 验证码、锁定、退避、WAF |
| 用户枚举 | 「用户名不存在」vs「密码错误」 | 统一文案 |
| 默认口令 | 中间件/设备 | 强制改密 |
| 短信/邮箱验证码 | 可爆破、可重放 | 限频、一次性、绑定场景 |
| 多因素缺失 | 仅密码 | TOTP/WebAuthn（高价值账户） |
| OAuth 误配 | redirect_uri 不严、state 缺失 | 精确回调白名单、state |

## 二、会话管理

### 会话固定
登录前后的 `session id` 是否更换？不换则攻击者可预置。

### 会话失效
- 注出是否真正清会话
- 改密是否踢掉旧会话
- 超时与绝对超时

### 会话劫持
- Cookie 被 XSS/网络窃取
- 公共电脑不退出
- Session ID 过短可爆破

## 三、JWT 速记

```text
header.payload.signature
```

| 风险 | 说明 |
|------|------|
| `alg: none` | 不验签（历史问题，库与配置要查） |
| 弱密钥 | HS256 密钥可被爆破 |
| 密钥混淆 | 公钥当 HMAC 密钥 |
| 无法主动失效 | 需黑名单/短过期+刷新 |
| 敏感信息进 payload | Base64 可读，不是加密 |

**前端**：优先 `HttpOnly` Cookie 存会话标识；若用 JWT，短有效期 + 安全存储方案要评估。

## 四、越权（Access Control）

| 类型 | 含义 | 例子 |
|------|------|------|
| 垂直越权 | 低权做高权事 | 普通用户调 `/admin/delete` |
| 水平越权 | 同权看/改别人的资源 | `order?id=123` 换成 124 |
| IDOR | 不安全的直接对象引用 | 顺序 ID/文件名可猜 |

### 测试方法

1. 登录两个账号 A/B
2. 用 A 的会话访问 B 的资源 ID
3. 改方法 GET→POST/PUT/DELETE
4. 改角色字段、JWT payload、Cookie 中的用户 ID（若前端可控）
5. 未登录直接访问

### 修复

- **服务端**按「当前主体 + 资源归属」校验
- 不要信任前端传的 `user_id`/`role`
- 用随机不可猜 ID 或仍然强制校验
- 网关鉴权 ≠ 对象级授权

## 五、密码存储与重置

- 存储：bcrypt/scrypt/argon2 + 盐
- 重置令牌：一次性、短时、绑定用户与场景、不可枚举
- 重置链接不要泄露到 Referer 第三方
- 邮件/短信口令要有有效期与尝试次数限制

## 六、检查表（面试/实操常用）

- [ ] 是否可爆破
- [ ] 是否用户枚举
- [ ] 登录后会话是否更换
- [ ] 注出/改密是否失效旧会话
- [ ] 水平越权是否可测
- [ ] 管理接口是否垂直越权
- [ ] 重置流程是否可重放
- [ ] JWT 配置是否安全
