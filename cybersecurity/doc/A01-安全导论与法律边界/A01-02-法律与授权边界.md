# A01-02 · 法律与授权边界

## 学习目标

- 明确什么能做、什么绝对不能做
- 理解「授权」在渗透测试中的法律意义
- 建立终身受用的合规习惯

> **红线一句话**：没有书面授权，不对接入公网或他人系统的任何「测试」。

## 一、中国相关法律（要点级）

| 法律 | 与渗透相关的核心点 |
|------|-------------------|
| 《网络安全法》 | 不得从事非法侵入网络、干扰正常功能、窃取数据等危害网络安全的活动 |
| 《刑法》第 285/286 条 | 非法侵入计算机系统、破坏系统、非法获取数据可构成犯罪 |
| 《数据安全法》《个人信息保护法》 | 数据与个人信息泄露、违规处理的责任 |
| 《治安管理处罚法》 | 未构成犯罪的侵扰、干扰行为仍可能处罚 |

**记住**：「只是看看」「没拿到数据」「没有造成损失」都不一定免除责任。是否「入侵」「非法控制」「破坏」由法律与证据认定，不是你自我感觉。

## 二、授权测试 vs 违法渗透

| 合法授权测试 | 违法/高风险行为 |
|--------------|-----------------|
| 有书面授权书 / 合同 / SRC 公开规则 | 自己觉得目标「漏洞很明显」去试 |
| 范围、时间、方法事先约定 | 扩大到授权外的 IP、域名、系统 |
| 仅在约定环境操作 | 使用真实用户数据、拖库、公开披露 |
| 发现问题按约定提交 | 未提交先发社交媒体「展示成果」 |
| 留存操作记录备查 | 清日志、留后门、横向到内网未授权主机 |

## 三、授权文件至少包含什么

1. 测试目标（IP/域名/应用名，最好带资产清单）
2. 测试时间窗（开始/结束时间）
3. 允许的技术手段（是否可爆破、是否可 DoS——通常 **禁止 DoS**）
4. 联系人与应急停止方式（出了问题找谁、如何立刻停）
5. 数据处理约定（能否下载、如何脱敏、如何销毁）
6. 书面签署（邮件书面确认通常也可，但最好有正式文件）

## 四、练习环境白名单（法律与伦理安全）

| 允许练习 | 不要碰 |
|----------|--------|
| 本地虚拟机靶场（DVWA、SQLi-labs…） | 公司生产系统（除非明确授权） |
| VulnHub / HackTheBox / TryHackMe 等约定平台 | 随机扫公网、踩点陌生站点 |
| 各厂商公开 SRC 且遵守其规则 | 未授权的「帮朋友看后台」 |
| 竞赛 / 训练营明确提供的环境 | 论坛里流传的「目标列表」 |

## 五、SRC（安全应急响应中心）怎么玩

1. 读规则：范围、禁止项、赏金、披露时间
2. 只测 scope 内资产；发现连锁漏洞也要先报备
3. PoC 最小化：能证明即可，不拖数据
4. 报告：复现步骤 + 影响 + 修复建议
5. 修复验证要在对方允许的时间后再看

## 六、日常工作习惯（合规内建）

- 所有测试先要授权截图/邮件归档
- 靶场与真实环境网络隔离
- 脚本里写清楚「目标范围」变量，避免误扫
- 报告中的敏感信息脱敏
- 不把客户数据传到第三方在线工具

## 自测

1. 朋友说「帮我看下我们公司网站有洞没」，你可以直接开扫吗？正确流程是什么？
2. 授权书里为什么必须写「禁止 DoS」类条款？
3. SRC 挖到高危，正确动作是发推特炫耀吗？
