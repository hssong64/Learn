# A01-03 · 核心安全概念

## 学习目标

- 掌握 CIA 三元组、身份认证、授权、审计
- 理解威胁、脆弱性、风险、影响的关系
- 会用攻击面思维审视一个 Web 应用

## 一、CIA 三元组

| 属性 | 含义 | 被破坏的典型场景 | Web 例子 |
|------|------|------------------|----------|
| **C Confidentiality** 机密性 | 数据不被未授权者获取 | 泄露、拖库 | SQL 注入读库 |
| **I Integrity** 完整性 | 数据不被未授权篡改 | 篡改、伪造 | 改价格、改权限字段 |
| **A Availability** 可用性 | 授权用户可用 | 宕机、资源耗尽 | DoS、死循环、锁表 |

衍生概念：
- **AAA**：Authentication（你是谁）、Authorization（你能做什么）、Accounting（你做了什么）
- **Non-repudiation** 不可抵赖：签名/审计证明行为确实发生

## 二、核心术语

| 术语 | 定义 | 记忆技巧 |
|------|------|----------|
| **资产 Asset** | 需要保护的东西（数据、服务、账号） | 先问：保护什么 |
| **威胁 Threat** | 可能造成伤害的事件或主体 | 谁/什么会来打 |
| **脆弱性/漏洞 Vulnerability** | 资产的弱点 | 门锁坏了 |
| **风险 Risk** | 威胁利用脆弱性对资产造成影响的可能性与程度 | 风险 = f(威胁, 脆弱性, 影响) |
| **攻击面 Attack Surface** | 所有可被触及的入口总和 | API + 文件上传 + 登录口… |
| **纵深防御 Defense in Depth** | 多层防护，一层被破仍有其他层 | 不靠一个 WAF |

## 三、认证与授权（必须分清）

```text
认证 Authentication：你是谁？（密码、短信、SSO）
授权 Authorization：你被允许做什么？（RBAC、ACL）
```

**常见漏洞思维**：
- 认证弱点：弱密码、无锁定、可爆破、JWT 可伪造
- 授权弱点：水平越权（看别人的订单）、垂直越权（普通用户当管理员）
- 前端隐藏按钮 ≠ 没有权限；**权限判断必须在服务端**

## 四、加密与哈希（概念层）

| 手段 | 用途 | 特点 | 例子 |
|------|------|------|------|
| 对称加密 | 保机密 | 加解密同一密钥 | AES |
| 非对称加密 | 保机密+签名校验 | 公钥加密/私钥解密 | RSA、TLS 握手 |
| 哈希 | 完整性、口令存储 | 不可逆、易碰撞设计 | SHA-256、bcrypt |
| 编码 | 不是加密 | 可还原 | Base64、URL encode |

**口令存储**：不要明文、不要裸 MD5/SHA1；用 bcrypt/scrypt/argon2 + 加盐。

## 五、信任边界与攻击面清单（Web）

从浏览器到数据库，每一条都是攻击面：

```text
浏览器（DOM、扩展、CSRF）
  → CDN / WAF
    → Web 服务器（Nginx/Apache 配置）
      → 应用框架（路由、模板、反序列化）
        → 鉴权与会话
          → API（注入、越权、SSRF）
            → 数据库 / 缓存 / 对象存储
              → 内网服务、后台、文件系统
```

问自己的三个问题：
1. 用户输入从哪里进来？
2. 信任了什么头、Cookie、参数？
3. 失败与异常路径是否安全？

## 六、安全设计小清单（SDL 思维）

- 默认最小权限
- 服务端校验一切客户端数据
- 错误信息不泄露栈/SQL/路径
- 敏感操作二次确认与审计
- 依赖与中间件持续更新

## 自测

1. 用 CIA 分析：用户购物车被改成负数，破坏的是哪一项？
2. 「验证码」主要解决认证还是授权问题？为什么？
3. 前端把删除按钮 `display:none`，算不算修复越权？
