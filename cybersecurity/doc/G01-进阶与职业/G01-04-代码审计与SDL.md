# G01-04 · 代码审计与 SDL

## 学习目标

- 理解安全开发生命周期
- 会做基础代码审计（从 Web 常见洞开始）
- 把安全左移到需求与设计

## 一、SDL（Security Development Lifecycle）

```text
需求 → 设计 → 实现 → 测试 → 发布 → 运营
  ↑      ↑      ↑      ↑      ↑      ↑
 威胁   架构  编码  审计  基线  监测
```

| 阶段 | 实践 |
|------|------|
| 需求 | 安全需求、隐私、合规 |
| 设计 | 威胁建模（STRIDE）、攻击面 |
| 实现 | 安全编码规范、依赖管理 |
| 测试 | SAST/DAST/IAST、渗透测试 |
| 发布 | 清单、配置基线、应急计划 |
| 运营 | 监控、补丁、SRC、复盘 |

## 二、代码审计入门流程

```text
1. 明确入口（路由、控制器）
2. 跟数据流：source → sink
3. 核查鉴权与对象归属
4. 查危险函数与配置
5. 验证、记录、建议
```

## 三、Source / Sink 速查

| 语言 | Source | Sink |
|------|--------|------|
| PHP | `$_GET/$_POST` | `echo`、`include`、`mysqli_query`、`unserialize` |
| Java | 请求参数 | SQL 拼接、`Runtime.exec`、反序列化 |
| Node | `req.query`、body | `innerHTML`、`eval`、`child_process` |
| Python | `request.args` | `os.system`、`pickle`、模板 |

## 四、审计优先点

1. 鉴权注解/中间件是否覆盖新路由
2. SQL/命令/模板拼接
3. 文件上传与路径
4. 权限校验是否按对象
5. 反序列化/XXE
6. 密钥与日志
7. 依赖 CVE

## 五、安全编码规范（抽样）

- 参数化 SQL
- 输出编码
- 白名单校验
- 最小权限
- 错误不泄露内部信息
- 依赖锁定与审计
- 密钥进配置中心/密钥管理，不进仓库

## 七、前端在 SDL 中的位置

- 组件库统一安全转义
- 依赖治理与 lockfile
- CI 加 lint/secret scan
- 需求评审提出「本功能有无越权/注入面」
- 与安全同学共建 CSP、Cookie 规范
