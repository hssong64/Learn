# C01-03 · 前端开发者安全视角

## 学习目标

- 把前端日常编码映射到安全风险
- 形成「安全代码审查」的前端检查表
- 知道从开发岗位切入安全的练手方式

## 一、你每天写的代码里的风险

| 前端写法 | 风险 | 应对 |
|----------|------|------|
| `innerHTML` / `dangerouslySetInnerHTML` | DOM XSS | 文本节点、白名单净化 |
| 字符串拼 HTML/URL | 注入、开放重定向 | 编码、URL 白名单 |
| `eval` / `new Function` | 代码注入 | 删除，改模块化 |
| `localStorage` 存 token | XSS 窃取 | HttpOnly Cookie 或短期 token |
| `postMessage` 不校验 origin | 跨窗口劫持 | 严格 origin 列表 |
| 反序列化 `JSON.parse` 后拼页面 | XSS / 原型污染 | 结构化输出、净化 |
| 依赖包随便升级 | 供应链/原型污染 | 锁版本、审 lockfile |
| 前端路由守卫当权限 | 越权 | 服务端鉴权 |

## 二、DOM XSS 前端清单

```javascript
// 危险
el.innerHTML = urlParams.get('q')

// 更安全
el.textContent = urlParams.get('q')
```

检查来源：
- `location` / `document.URL` / `document.referrer`
- `postMessage` 数据
- 用户资料、富文本、Markdown 渲染
- 第三方 SDK 回调

检查汇点（Sink）：
- `innerHTML` / `outerHTML` / `document.write`
- `eval` / `setTimeout(string)`
- `href`/`src` 赋值（`javascript:`）
- jQuery `$()`、模板引擎未转义

## 三、前端安全开发检查表

- [ ] 所有渲染是否默认转义
- [ ] 跳转 URL 是否白名单
- [ ] API 是否带鉴权且服务端再校验对象归属
- [ ] Cookie 属性是否正确
- [ ] 上传组件是否校验类型/大小/内容
- [ ] 依赖是否锁版本、是否扫描
- [ ] 错误信息是否泄露内部路径/堆栈
- [ ] 调试接口、mock 数据是否上线
- [ ] CORS 是否最小放行
- [ ] 敏感操作是否有二次确认与审计

## 四、供应链与依赖

1. **锁定**：`package-lock.json` / `pnpm-lock.yaml` 提交进库
2. **最小依赖**：功能简单就别装巨型库
3. **审计**：`npm audit`、Socket、Snyk（授权范围内）
4. **安装脚本**：警惕 `preinstall` 恶意脚本
5. **原型污染**：merge 类库历史漏洞多

## 五、从开发到安全的练手方式

| 方式 | 说明 |
|------|------|
| 自审旧项目 | 用本节检查表打分 |
| 安全重构 | 把一个 innerHTML 场景改安全 |
| 写 PoC | 对自己的 DVWA/靶场写最小复现 |
| 开发安全组件 | 转义、URL 校验、富文本白名单组件 |
| 参与 SDL | 需求/设计阶段加入威胁分析 |

## 六、思维转变

| 开发默认 | 安全默认 |
|----------|----------|
| 让功能跑通 | 让错误路径也安全 |
| 信任输入 | 不信任任何客户端数据 |
| 报错给用户友好 | 报错不给攻击者信息 |
| 先上线再补 | 高危项阻断发布 |
| 用户都是好人 | 用户可能就是攻击者 |

## 动手练习

1. 在旧项目里搜索 `innerHTML`、`eval`、`document.write` 并处理
2. 写一个「安全的 URL 跳转」工具函数并测 `javascript:` / `//evil`
3. 给你的组件库加 XSS 自测用例
