# C01-01 · Web 应用架构与数据流

## 学习目标

- 从请求到数据库画出完整数据流
- 标出每一段的信任边界与潜在注入点
- 建立「漏洞长在数据流交叉处」的直觉

## 一、典型现代 Web 架构

```text
[浏览器 SPA / SSR]
    ↓ HTTPS
[CDN / WAF / API 网关]
    ↓
[前端静态资源 + Node/SSR]（可选）
    ↓
[业务后端 API]（鉴权、校验、业务）
    ↓
[数据库 / 缓存 / 消息队列 / 对象存储 / 第三方 API]
```

## 二、一次「下单」的数据流练习

```text
用户输入地址、优惠码、数量
  → 浏览器校验（可被绕过）
  → HTTPS 请求到 API
  → 网关鉴权（Token 是否有效、是否重放）
  → 参数解析（JSON、查询串、头）
  → 业务逻辑（价格计算、库存、权限）
  → SQL/NoSQL/ORM
  → 写库、发消息、调支付
  → 返回订单号
```

每一箭头都可能是漏洞点：
- 输入未过滤 → XSS/SQLi/命令注入
- 权限只在前端 → 越权
- 价格在前端算 → 逻辑漏洞
- 回调未验签 → 支付伪造

## 三、信任边界清单

| 边界 | 常见错误信任 |
|------|----------------|
| 浏览器 → API | 信任所有参数、头、Cookie |
| 微服务 A → B | 无内部认证、可伪造来源 |
| 应用 → 文件系统 | 路径拼接、上传 |
| 应用 → 第三方 | SSRF、回调未验签 |
| 前端路由 | 以为隐藏菜单 = 无权限 |

## 四、注入点地图（从数据流看）

| 输入源 | 可能汇入 | 典型漏洞 |
|--------|----------|----------|
| URL/Query/Body | SQL、命令、模板 | SQLi、SSTI、命令注入 |
| 文件名/内容 | 文件系统、解析器 | 上传、解析漏洞、路径穿越 |
| Header（UA、XFF） | 日志、缓存、鉴权 | 日志注入、缓存欺骗、IP 伪造 |
| JSON/XML | 反序列化、XXE | RCE、文件读取 |
| 用户资料（昵称） | 页面渲染 | 存储型 XSS |
| 富文本/Markdown | HTML | 过滤不当 XSS |
| URL 参数跳转 | Location | 开放重定向 |

## 五、架构级安全控制

1. **网关统一鉴权**，后端不信任何「前端传来的心」
2. **参数白名单**比黑名单更稳
3. **ORM 参数化**默认开启，手写 SQL 必须绑定参数
4. **对象级鉴权**（IDOR）：每个资源校验归属
5. **审计日志**：谁在何时对哪个对象做了什么

## 六、前端经验直接迁移

- 你写的 API 调用层 = 攻击者重放/改包层
- 你处理的表单校验 = 必须在服务端重复
- 你用的 JWT/Cookie 方案 = 会话攻击面
- 你搭的 SSR/同构渲染 = 服务端 XSS、SSRF 新面

## 动手练习

1. 任选你做过的一个页面，画出数据流并标 3 个信任边界
2. 找出「只在前端校验」的 3 处逻辑（自己项目）
3. 对一条 POST 请求，在纸写出从浏览器到 SQL 的全部组件
