# C01-02 · 浏览器安全模型

## 学习目标

- 吃透同源策略、CORS、CSP、Cookie 属性
- 理解这些机制「防什么 / 不防什么」
- 为 XSS、CSRF、点击劫持打理论地基

## 一、同源策略（SOP）

**同源** = 协议 + 主机 + 端口都相同。

`https://app.example.com:443` 与 `http://app.example.com` 不同源；  
`app.example.com` 与 `api.example.com` 不同源。

| 通常限制 | 通常允许 |
|----------|----------|
| 跨域读 DOM / Cookie / localStorage | 跨域**写**请求（no-cors 有限） |
| 跨域读响应（未放行） | 加载图片/脚本/CSS（是否执行看更多策略） |
| XMLHttpRequest/ fetch 跨域读 | 发送请求但读不到响应 |

**安全意义**：防止 `evil.com` 的脚本随便读 `bank.com` 的数据。

## 二、CORS（受控跨域）

服务端用响应头**明确放行**：

```http
Access-Control-Allow-Origin: https://app.example.com
Access-Control-Allow-Credentials: true
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Allow-Methods: GET, POST
```

### 高危误配

| 配置 | 风险 |
|------|------|
| `ACAO: *` + 带凭证 | 规范禁止组合，但错误实现会出事 |
| 反射任意 Origin | 等于任意站点可带凭证读响应 |
| 只校验域名后缀不严 | `evil-app.example.com` 冒充 |

**预检**：非简单请求先发 `OPTIONS`。

## 三、Cookie 属性

```http
Set-Cookie: session=s3cret; HttpOnly; Secure; SameSite=Lax; Path=/; Domain=example.com
```

| 属性 | 作用 |
|------|------|
| HttpOnly | JS 无法读，防 XSS 偷 Cookie |
| Secure | 仅 HTTPS 发送 |
| SameSite=Lax/Strict/None | 跨站发送策略，防 CSRF/跟踪 |
| Domain / Path | 作用范围，配宽会误伤其他应用 |
| Expires / Max-Age | 生命周期 |

## 四、CSP（内容安全策略）

```http
Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-xxx'; object-src 'none'; base-uri 'self'
```

作用：即使有 XSS，限制脚本来源可显著降低危害。  
注意：`unsafe-inline`、`unsafe-eval` 会大幅削弱 CSP；CDN 与第三方脚本要精确保留。

## 五、其他浏览器防护

| 机制 | 防什么 |
|------|--------|
| X-Frame-Options / frame-ancestors | 点击劫持 |
| X-Content-Type-Options: nosniff | MIME 嗅探 |
| Referrer-Policy | Referer 泄露 |
| Permissions-Policy | 摄像头等能力 |
| Trusted Types | DOM XSS 纵深 |

## 六、防什么 / 不防什么

| 机制 | 防 | 不防 |
|------|----|------|
| SOP | 跨站读数据 | 你站内自己的 XSS |
| CORS | 未授权跨域读 | 服务端越权、注入 |
| HttpOnly | XSS 读 Cookie | XSS 在页面上作恶、CSRF |
| SameSite | 多数 CSRF | 子域 XSS、同站攻击 |
| HTTPS | 窃听篡改 | 应用逻辑漏洞 |
| CSP | 部分 XSS 利用 | 完美无 XSS |

## 动手练习

1. 用两个不同端口本地服务试 CORS 放行前后差异
2. 在 DevTools 观察 Cookie 的 HttpOnly/SameSite
3. 给一个 demo 页加最小 CSP 并测试内联脚本是否被拦
